## 🎯 项目背景 & 痛点（第 2 页）
### 为什么要做这个系统？（3 个真实业务痛点）
1. **手工排课效率极低**：Excel 手工排课 40 个班，一位教务要花 7~10 天，改一门课牵一发动全身；
2. **冲突靠人肉**："老师 A 被排在 1 班 3 节，同时 2 班 3 节也排了老师 A" 这种冲突，传统方式要学生/老师开课一两周后才发现；
3. **教学评价数据扔了**：学生填的评教问卷，只有平均分看一眼，大量文字点评沉淀不下来，没办法生成可执行的改进建议。

### 项目目标
- **排课 0 冲突**（硬指标，必须 100% 做到）
- **三端可用**（教务 / 教师 / 学生，权限严格隔离）
- **AI 闭环**（排课软约束 + 评教分析，两个业务场景真落地）
- **生产可用**（7 项加固，能直接部署到学校内网）

term(学期) ─┬─ clazz(班级) ─ student(学生)

## 🧠 核心亮点：AI 智能排课引擎（第 6 页，答辩重中之重！）
**标题**：异步状态机 + LLM 启发式评分 · 实测 0 冲突

**① 状态机 5 态 + @Async 双池**
```
PENDING → [点击开始排课] → RUNNING → [算法完成] → COMPLETED
                                         ↓ [异常]
                                       FAILED（堆栈存 run_log）
```
> 为什么异步？—— HTTP 30s 超时 vs 真实排课 5~10 分钟；自定义线程池 schedule(4/8/16) + sys(4/20/200)，CallerRunsPolicy 背压不丢任务。

**② "传统算法 + AI 评分" 分工（体现你真懂 AI 落地不套壳）**
| 层面 | 交给谁做 | 为什么 |
|---|---|---|
| 硬约束（0 冲突保证）| Java 本地 HashMap 计数 O(1) | 必须精确，AI 给不了 100% |
| 软约束（跨校区少、主课上午、体育不连排）| LLM Qwen3-32B 启发式 1~10 评分 | 多目标优化，写 if-else 300 行也调不出来 |

**③ 实测数据（右下角放截图，说服力强）**
> ✅ 9 个班 26 门课 · 6 轮迭代 · **冲突数：0**
> ✅ AI 对比纯贪心"跨校区次数" ↓ 62%
> ✅ 同班级所有学生课表完全一致（抽取 180 名学生 × 3 班级校验）

## 🎤 答辩 3 个小技巧
1. **第 6 页（AI 排课）一定多花 1 分钟**：这是全场独一份的亮点，别人项目都是 CRUD，你有 AI 落地产出指标，老师印象分 +20；
2. **第 8 页（7 项加固）要强调"我主动做的"**：老师最喜欢"自己主动发现问题并解决"的学生，不是等着别人给需求才写代码；
3. **被问倒了别慌**：先说"这个场景我还没遇到过，但我会从 X、Y、Z 三个角度考虑"（X 约束 / Y 折中 / Z 验证），老师看的是你的思维，不是你的背题量。
